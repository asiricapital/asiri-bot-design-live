# خطة ترتيب مستودعات أحمد العسيري

## الحالة الحالية

### `asiri-bot`

المستودع الإنتاجي الأساسي لمنصة Asiri Capital. يبقى خاصًا ويستقبل التطوير عبر فروع وPull Requests فقط.

### `ASIRI-2026`

مختبر قديم يحتوي على مولد ملفات وWorkflows غير مناسبة للإنتاج، ومنها الكتابة إلى نفس الفرع و`git push --force`. لا يتم تشغيل هذه الأدوات على المستودع الرئيسي.

الخيار المقترح بعد استقرار v6.4:

- إما تحويله إلى `asiri-labs` كمختبر واجهات واختبارات منفصل.
- أو أرشفته إذا لم توجد تجربة محددة له.
- إزالة `AUTO-BUILD.js` والـWorkflow الذي يعيد إنشاء المشروع ويدفع التغييرات تلقائيًا.

### `scrcpy`

نسخة عامة من مشروع لا يرتبط بمنصة الأسهم أو أعمال المنافسات. طلب المستخدم حذفه من حسابه بعد الانتهاء من مرحلة v6.4 ودراسة المشاريع.

## ترتيب التنفيذ

1. دمج v6.4 بعد اجتياز CI والمراجعة.
2. مراقبة الإنتاج لدورة مستقرة واحدة.
3. تنفيذ دراسة المشاريع الكبرى وتحديد ما سنبنيه فعلًا.
4. تحديد مصير `ASIRI-2026`: إعادة تسمية وتنظيف أو أرشفة.
5. حذف مستودع `scrcpy` بعد نسخة احتياطية اختيارية والتأكد أنه ليس مستخدمًا في أي نشر أو Workflow.
6. توحيد أوصاف المستودعات وملفات README والسياسات الأمنية.
7. تفعيل حماية فرع `main` ومنع الدفع المباشر عند توفر الإعدادات المناسبة.

## الهيكل المستهدف

- `asiri-bot` — منصة Asiri Capital الإنتاجية.
- `asiri-labs` — تجارب الواجهات والاستراتيجيات غير الإنتاجية.
- `asiri-tender-intelligence` — منصة المنافسات الحكومية والملفات.
- `asiri-mcp` — موصل قراءة فقط عند جاهزية بيئة الموصلات.

لا يتم خلط مشاريع العمل والمنافسات داخل خادم التداول نفسه، لتقليل المخاطر والتعقيد.
